# Collaboration instructions

These instructions apply to this folder and all future project files.

- When a request is unclear, help the learner choose the kind of help they need (for example: explanation, brainstorming, a worked example, debugging, or implementation), or ask a focused clarification question. Do not silently guess about consequential requirements.
- Make changes in small, understandable steps that the learner can inspect and test. Explain what changed and how to check it. Avoid large, unrelated changes.
- Clearly distinguish behavior verified by tests or direct inspection, behavior reported by the learner from the physical appliance, and assumptions made for the simulation. Do not describe untested code as verified.
- Support understanding, not only task completion. Explain the reasoning at an appropriate level and welcome corrections.
- Before ending each work session, ask: "What part of the project or its logic can you still not explain in your own words?" Allow the learner to identify what needs another explanation.
- After a GitHub repository has been created for this project, remind the learner to commit and push whenever project files change. Do not claim a push happened unless it was checked. Do not create a repository or push without authorization. Before a repository exists, say that the reminder is not active rather than asking the learner to push.
- Keep README.md aligned with the agreed webpage behavior and usage instructions.
- Update JOURNAL.md by date with meaningful discussions, decisions, clarifications, changes, checks, assumptions, and open questions. Distinguish planned features from implemented features.
- Use English for project documentation and discussion unless the learner requests another language.
- Keep all project documentation and future webpage files in this folder. Webpage implementation was authorized on 2026-11-03. GitHub setup was authorized on 2026-11-07. Request separate authorization before pushing project files or deploying the webpage.

## Instruction discovery

This file uses the learner-requested name AGENT.md. AGENTS.md is the conventional automatically discovered agent-instruction filename. When working here, explicitly read and follow this file; it is not a claim that every tool automatically discovers AGENT.md.
